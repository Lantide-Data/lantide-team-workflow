# Workflow: update existing analysis

## Use when

Use this workflow to refresh, reproduce, explain, or revise a specifically identified Plan, Report, HTML Report, or recurring analysis. If no exact artifact can be identified, ask the user instead of choosing the latest file silently.

## Procedure

1. Identify the workspace, project, artifact type, and exact file or stable reference.
2. Read the current artifact and its evidence lineage. Treat chat summaries and old local copies as non-authoritative.
3. Compare the requested change with the existing contract:
   - revise the same Report for bounded wording, presentation, or evidence-backed updates that preserve the question and contract;
   - start a new formal Plan when the question, metric, grain, denominator, source, major time basis, or pipeline materially changes.
4. Confirm whether the user expects current live data, historical reproduction, or comparison between the two.
5. Load the live runtime skills for the chosen path and rerun only the evidence required to support the update.
6. Explain material differences using data change, method change, definition change, or unresolved uncertainty; do not guess.
7. Update the managed artifact through Lantide, preserve required lineage, and apply current review and verification rules.
8. Read back the updated artifact before summarizing or distributing it.

## Stop or escalate when

Stop when lineage is broken or ambiguous, the source snapshot is unavailable, the existing contract cannot support the requested claim, or the update would conceal a material methodology change. Ask whether to repair lineage, accept a disclosed limitation, or begin a new Plan.

## Completion criteria

- The exact original artifact was identified and read.
- The choice between revision and new Plan is justified.
- Data and methodology differences are distinguished.
- New claims have current evidence and limitations.
- The managed artifact, not only chat, contains the update.
